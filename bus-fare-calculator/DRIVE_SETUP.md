# Saving agreements to Google Drive

Every agreement generated by the app can be saved automatically into one
company Google Drive folder, so there is a single official record of all real
agreements. Each agreement also carries a unique reference number
(e.g. `ML-260725-4F7A`) printed on the document, which matches the saved file's
name in Drive — so a genuine agreement can always be checked against the record.

Until the four settings below are configured, the **Save to Drive** button
simply reports "Drive saving isn't set up yet" and printing/sharing continue to
work normally. Nothing breaks.

## Which account

Set up as the operator's own Google account (`bhuwan.garg1@gmail.com`). Do every
step below signed in as that account — the folder, the Cloud project and the
token must all belong to the same one.

The app asks for a single permission, `drive.file`, which reaches **only the
files this app itself creates**. It cannot read, list or alter anything else in
the account's Drive, so pointing it at a personal account does not expose the
rest of that Drive.

> The app signs in as this account using a stored refresh token. A Google
> "service account" is deliberately *not* used here: service accounts have no
> Drive storage quota of their own, so uploads into a normal Gmail Drive fail.

## One-time setup

### 1. Make the Drive folder

1. Sign in to Google Drive as your own account.
2. Create a folder, e.g. **Mahalaxmi Agreements**.
3. Open it. The URL ends with the folder id:
   `https://drive.google.com/drive/folders/`**`1AbCdEf...`** — copy that id.
   This is `GOOGLE_DRIVE_FOLDER_ID`.

### 2. Create the OAuth client

1. Go to <https://console.cloud.google.com/> (signed in as your Google account).
2. Create a new project, e.g. *Mahalaxmi Agreements*.
3. **APIs & Services → Library** → search **Google Drive API** → **Enable**.
4. **APIs & Services → OAuth consent screen** → User type **External** →
   fill in the app name and your email → **Save**. Under *Audience*, add
   your own account as a **Test user**.
5. **Important — then set the publishing status to "In production"**
   (same OAuth consent screen page, *Publishing status → Publish app*).
   While an app sits in *Testing*, Google expires its refresh tokens after
   **7 days**, and Drive saving would silently stop working a week after setup.
   Publishing avoids that. The only scope used here is `drive.file`, which
   grants access solely to files this app itself creates — it is not a
   "sensitive" scope, so publishing does not require Google's review process.
6. **APIs & Services → Credentials → Create credentials → OAuth client ID** →
   Application type **Web application**.
7. Under *Authorised redirect URIs* add exactly:
   `https://developers.google.com/oauthplayground`
8. **Create**. Copy the **Client ID** (`GOOGLE_CLIENT_ID`) and
   **Client secret** (`GOOGLE_CLIENT_SECRET`).

### 3. Get the refresh token

1. Open <https://developers.google.com/oauthplayground>.
2. Click the ⚙️ gear (top right) → tick **Use your own OAuth credentials** →
   paste the Client ID and Client secret.
3. In the left list, scroll to **Drive API v3** and select the scope:
   `https://www.googleapis.com/auth/drive.file`
4. Click **Authorise APIs** → sign in as your own account → **Allow**.
   (If a "Google hasn't verified this app" warning appears, choose
   *Advanced → Go to … (unsafe)*. It is your own app.)
5. Click **Exchange authorisation code for tokens**.
6. Copy the **Refresh token** — this is `GOOGLE_REFRESH_TOKEN`.

### 4. Add the settings to Vercel

In the Vercel project → **Settings → Environment Variables**, add all four for
the **Production** environment, then redeploy:

| Name | Value |
| --- | --- |
| `GOOGLE_CLIENT_ID` | from step 2 |
| `GOOGLE_CLIENT_SECRET` | from step 2 |
| `GOOGLE_REFRESH_TOKEN` | from step 3 |
| `GOOGLE_DRIVE_FOLDER_ID` | from step 1 |

Keep the client secret and refresh token private — anyone holding them can
write into that Drive folder. They are only ever read on the server; they are
never sent to the browser.

## Checking it works

Open the agreement page, fill in a customer, and press **Save to Drive**. On
success the status line reads "Agreement saved to the company Drive record"
with an **Open in Drive** link. The file is named
`ML-260725-4F7A - Ramesh Kumar.pdf`, and its Drive description records the
reference, customer, route, total and date.

## A note on preventing fake agreements

Saving to Drive plus a unique reference gives you a way to *verify* an
agreement: if a document's reference number is not in the Drive folder, or the
details do not match the saved copy, it did not come from the company.

It does not by itself *stop* someone from producing a document, because the
agreement page is publicly reachable — a person could open it and print
something without pressing Save. If you want to close that gap, the page can be
put behind a shared staff passcode so only your team can open the generator at
all. That is a small change and can be added whenever you want it.
